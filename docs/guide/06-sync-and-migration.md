# 06 · 同步与迁移

适用版本：0.1.0 ｜ 更新于 2026-10-10

两条链路解决两件事：**同步**是「把数据搬过去，目标结构可以自动建」；**迁移**是「整库结构 + 数据 + 索引一次性过库」。

## 入口

| 入口 | 动作 |
| --- | --- |
| 顶栏「数据库同步」 | 当前库整库同步（需先选中数据库） |
| 表节点菜单 / 表工具条「同步」 | 单表同步 |
| 顶栏「数据库迁移」 | 打开迁移向导（不需要先选中对象） |
| 顶栏「数据导出」「数据库备份」 | 见 [07](07-export-mask-backup.md) |

未满足前置条件的按钮会置灰，悬停提示直接写明缺什么（例如「请先在左侧选择一个数据库」）。

## 行数上限的统一语义

所有涉及行数上限的地方（导出、备份、单表同步、整库同步、迁移）都是同一个规则：

- 填 **`0` 或 `-1` = 不限制，处理全部行**；界面上有「全部行」快捷按钮，标签会变成「当前=全部行」；
- 整库操作时这是**每张表**的上限；
- 取数一律逐页（500 行 / 页）边取边写，不会因为「全部行」把整表堆进内存；
- 默认上限：导出 5 万、单表同步 5 万、整库同步每表 2 万、备份 10 万 / 5 万、迁移每表 20 万。

## 单表 / 整库同步

弹窗字段：

- **目标连接**：下拉，显示连接名、副标题显示引擎类型，可键入筛选；
- **目标库**：下拉，切换连接时自动拉取该连接的库列表，读取中禁用并显示「读取目标库…」，失败时把原始错误显示在下面并可点右侧按钮重试；
- **目标表**：单表同步时可改名，整库同步时同名落库；
- **目标表不存在时自动创建**；
- **最大行数**。

跨引擎落库方式：

| 目标 | 落法 |
| --- | --- |
| SQL → SQL | 自动建表（类型按目标方言渲染）后逐行写入 |
| SQL → Redis | 每行一个 string 键 `<表名>:<主键值>`，值是整行 JSON；弹窗里有说明 |
| SQL → MongoDB | 每行一个文档写进同名集合 |

### 结果报告

同步执行后弹窗不关，显示与迁移同款的逐表报告：

- 顶部标签：共 N 张表 / 已建目标 / 写入 / 失败 / 总行数 / 未写入行数；
- 表格每行：状态（已建目标 · 已写入 · 失败）、目标表或键前缀、行数（有失败时标红 `-N`）、说明；
- 失败行的**原始数据库报错**原样放进说明里，不改写；整行都是默认值的行会单独记「整行为空，未写入」；
- 通知条同时给一句话结论（例如「已同步 3 张表 / 1200 行到 postgres；1 张表失败：…」）。

一行都没写成功时按失败处理（返回错误而不是「成功 0 行」）。

## 数据库迁移

左右两栏分别是源与目标：连接下拉 + 数据库下拉（同样带加载态、重试与原始错误），源栏会显示统计出的基础表数量。

选项：

| 选项 | 说明 |
| --- | --- |
| 迁移表结构 | 建表 DDL（类型归一化、主键、非空、默认值、注释） |
| 迁移数据 | 逐页取数写入，布尔 / 数值 / 大字段按目标类型转换 |
| 迁移二级索引 | 结构建好后补建索引（PG / SQLite 索引名带表名前缀避免全局冲突） |
| 目标已存在 | 跳过该表 / 清空重建 / 追加数据 |
| 每表最多 | 行数上限，`0` 或 `-1` = 全部行 |

类型归一化举例：MySQL `tinyint(1)` → PG `boolean`（默认值 `0/1` 同步改成 `false/true`）、`decimal(10,2)` → `numeric(10,2)`、`blob` → `bytea`、`json` → `jsonb`、自增主键 → `serial/bigserial` 或 `bigint auto_increment`；反向也支持（PG 的 `nextval(...)` 会被识别为自增而不是原样搬过去）。

数据迁完后，PG 目标会对序列主键执行 `setval(pg_get_serial_sequence(...))` 回填，避免后续插入撞主键。

执行中有进度条，结束后给出逐表报告（状态 / 表 / 行数 / 说明），失败的表不影响其余表继续，错误原文保留在说明里。
