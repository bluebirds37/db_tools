# 02 · 连接管理

适用版本：0.1.0 ｜ 更新于 2026-10-14

## 新建连接

点左侧「连接」区右上的 `+`，对话框分两步：

1. **选类型**：左侧是按类别归组的导航（全部 / 关系型 / 文档型 / 键值 / 搜索引擎 / 向量库），右侧支持网格与列表两种排布、可搜索、显示最近用过的类型；**双击某个类型直接进入第二步**。
2. **填参数**：名称、主机、端口、用户名、密码、默认库（可选）。切换类型会自动带上该引擎的默认端口与主机。

各引擎的差异化字段：

| 引擎 | 说明 |
| --- | --- |
| SQLite | 只填数据库文件路径，不出现主机 / 端口 / 账号 |
| Redis | 「默认数据库」是 `db0…db15` 下拉（含「连接配置里的默认库」），不是文本框 |
| Elasticsearch / Qdrant | 默认不显示用户名密码（用 API Key 或无认证时留空即可） |

## 测试与保存

「测试连接」用当前填写的参数真实建连一次，成功显示结果，失败**原样显示后端返回的原因**（不改写、不猜测）。保存后连接出现在左侧列表，可右键或点行内菜单进行 编辑 / 删除 / 刷新库列表。

## 建连超时

所有建连都有时限，避免连不上的库把界面卡死：

- 默认 **6 秒**；
- 想改就在连接的选项里填 `connect_timeout`（单位秒，允许 1–120）；
- 超时或失败的连接会进入 3 秒冷却，期间重复点击不会反复发起建连；
- 每个连接各自持有会话与门禁，**慢连接不会阻塞其他连接**；切换数据库时右侧立即进入加载态，过期响应会被丢弃。

| --- | --- | --- |
| MySQL | 3306 | |
| PostgreSQL | 5432 | |

新建时按类型自动带上这些默认端口，需要另建实例（比如同一台机器上的第二个 MySQL）改端口就行。

## 存储位置

连接信息只存在本机的 `~/.db_tools/connections.json` 里，程序不内置任何连接：第一次运行就是空列表，左侧会显示「还没有连接」并给出新建入口。删掉这个文件等于清空全部连接（其他数据不受影响）。

## 删除连接

删除只移除本机保存的连接配置，不会动数据库里的任何数据。删除当前活动连接会同时清空已选库表。
